# Catalog and rights

The candidate inventory retains all 332 names from `figlet@1.12.0`. Only the 19 entries explicitly selected in `catalog/rights-decisions.json` are shipped. Their original MIT or WTFPL redistribution notices were reviewed and retained beside the unchanged font bytes. The other 313 remain unavailable until their rights evidence is reviewed. The engine license does not clear fonts.

Run `node scripts/import-catalog.mjs` after an intentional rights review; `make test-render` checks reproducible import, source/header hashes, identifiers, packaged notices, family mapping, effective glyph coverage and representative output. The importer refuses upstream byte drift. The candidate inventory contains metadata, never unresolved font binaries.

Future Thin and Smooth explicitly derive from Future. Emboss headers describe the Emboss 2 transformation. These share family IDs; other available fonts remain separate. Unknown tags are `null`. Every font has foreground and background slots. Extra slots come only from `catalog/color-mappings.json`, a reviewed list of the characters each font draws for a role; the importer rejects a mapping that names a character the font never draws or a font that is not approved. Fonts without a reviewed mapping have `colorMapping: null`. The original ANSI Compact recipe IDs remain valid; new IDs use the `figlet/` namespace. Font hashes and renderer versions are independent of those stable IDs.

The worker fetches only the selected font, verifies its SHA-256 before parsing, and caches it for that worker. Glyph coverage includes nonblank defined glyphs and space; blank placeholders and absent code points are reported without changing input. Requests retain the skeleton's sequence checks so late loads cannot replace current output. A temporary load failure can be retried. Native Style selection is provided to exercise the renderer; family gallery browsing remains #15.

## Looks and filters

The importer records `looks` for each font from the characters its A–Z glyphs draw: blocks, shaded (░▒▓), lines (box drawing), braille, letters, enclosed (circled letters), wide (full-width forms) and symbols. A font can have several looks; Linguaholic Shadow 3D is both blocks and lines. Looks describe what is drawn, not reviewed style tags, which stay `null`. The gallery's filters combine a name search (family or variant), looks, maximum columns and rows for the current text (measured from the live previews), and "Supports every character in my text" (from recorded glyph coverage). A family with no recorded look stays visible and marked when a look filter is on, so missing data is never shown as a negative match. Filters survive text and variant changes, and an empty result offers **Clear filters**. `make test-render` checks the recorded looks; the browser suite covers combined filters, separate 3D and line families, dimension and character filters, and the empty state.
