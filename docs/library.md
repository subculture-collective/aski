# Local library

Favorites, saved text and saved designs (and later palettes and collections) are stored in the browser's IndexedDB database `aski-library`, object store `records`. It is separate from the `aski:draft` key in localStorage. IndexedDB can also hold artifact bytes later, which localStorage cannot.

Each record uses the envelope from the [account contract](account-sync-contract.md): `namespace`, UUID `id`, `type`, `schemaVersion: 1`, `payload`, `revision`, `deletedAt`, `createdAt` and `updatedAt`. Records made before sign-in use the `anonymous` namespace and revision 0, meaning no server has acknowledged them. Removing an anonymous record deletes it; tombstones begin with account sync.

A favorite payload is a stable `familyId` and optional `variantId`. It holds no text or rendered output, so applying it changes only the style of the current design. Favorites are unique by family and variant.

Saved text (`input`) holds the original text and a name. Opening it replaces the editor text and keeps the current style, so the same words can be tried in another font. A saved design holds a name, a full version-1 recipe with its own recipe UUID, font SHA-256 and renderer version, and a snapshot of the exact output text with its columns and rows. The snapshot is never re-rendered. Opening a design restores its recipe as one undoable edit. If this build lacks the design's font or renderer version, the current work is left alone, an explanation appears, and **Copy saved text** still copies the snapshot. If the restored recipe renders differently from its snapshot, the studio says so. Names are 1–120 characters; defaults come from the first line of text. Rename and delete (with confirmation) apply to both kinds.

A collection holds a name only; equal names are separate collections. A `membership` record links one collection to one favorite or saved design (`itemType` and `itemId`) and is unique per collection and item, so an item can be in several collections without being copied. Removing a membership leaves the item alone. Deleting a collection deletes its memberships in the same IndexedDB transaction and keeps the styles and designs. Deleting a favorite or design also deletes the memberships that point at it. Collections label styles and designs differently, and opening a member applies the style or reopens the design.

**Original files.** When saving a design, PNG and SVG can be kept too (default image settings: 2× scale, 16 pixels of padding, solid background, seamless blocks if on). The bytes go into a second IndexedDB store, `artifacts` (database version 2), with their SHA-256, MIME type, byte length, pixel size and the font and renderer that made them. The design lists their UUIDs. Files are never regenerated: **Download original** returns the stored bytes after checking their hash, so a later font or renderer change cannot alter them, even when this build can no longer render the design's recipe. The design record is saved before its files, so if the browser has no room for the files the design and draft are kept and a message says so. Deleting a design deletes, in the same transaction, only files no other design references.

Records with an unknown schema version, type or font are counted in a warning and left unchanged in storage. If IndexedDB is unavailable or a write fails, favorites still work until the page closes and a warning says so. The browser library never contacts the account service. When signed in, the visitor chooses between this library and the [account library](account-library.md); neither is copied into the other unless the visitor imports it. Database version 3 adds an `imports` store holding, per account, the map from browser record UUIDs to account UUIDs. Version 4 adds a `sync` store holding, per account, the change-log cursor, the queue of unsent changes and the account's address; that account's records are cached in `records` under the namespace `account:<user ID>`.

`make test-storage` covers record validation, favorite uniqueness, name limits, unreadable records and a design whose renderer changed after saving, and collection membership and deletion rules. The browser suite covers favorite/unfavorite, reload, applying a favorite to new text with the account API unreachable, unreadable records kept in place, touch use, two designs from one text restoring their own variants and snapshots, saved text reopening in the current style, rename/delete across reloads, a design from an unavailable renderer, and collection create/rename/delete with mixed items in several collections by mouse, keyboard and touch.
